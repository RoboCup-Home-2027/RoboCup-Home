|  |  |  |

**三 拟采用的技术路线**

总体目标是完成建图、多点导航、寻物和语音报告；采用“先稳定完成比赛任务，再扩展识别与避障能力”的实施顺序。

**传感器联调 → 标定与建图 → Nav2导航 → 视觉寻物 → 语音报告 → 比赛验收**

图 2 ROS2 比赛系统分层架构

|  |  |
|:--:|:--:|
| **环节** | **实施要点** |
| 建图定位 | 标定相机内参；用 N10P 建图，检查 TF、里程计和狭窄通道；保存地图。 |
| 导航 | Nav2 完成入口、房间、多点和出口；配置 footprint、膨胀、限速、重规划和急停。 |
| 寻物交互 | 先用 ArUco/数字标签识别和多帧确认，再接入 YOLO；结果同步屏幕、动作和 TTS，并保留置信度与目标坐标。 |
| 系统保障 | 统一 launch、参数和日志；rosbag 复现；标签丢失、定位跳变或通信异常时立即清零速度并提示人工接管。 |

**四 关键技术说明**

定位采用激光雷达、里程计与 TF 树联合校验，先完成静态地图，再以 AMCL
做重定位；导航层采用行为树组织“到点—识别—确认—播报”，通过代价地图膨胀、速度限制和重规划降低碰撞风险。

视觉层采用“标签优先、模型增强”的策略：标签用于稳定完成比赛任务，YOLO
用于扩展真实物体识别；每次识别需连续多帧一致，并记录置信度、目标位置和时间戳。系统统一管理
launch、参数和日志，使用 rosbag
复现问题；标签丢失、定位跳变或通信异常时立即清零速度并提示人工接管。

**五 可行性与验收**

组件、源码、教程和统一启动流程齐备，团队覆盖视觉、ROS、机械、交互。按“联调—建图—导航—寻物—语音—演练”推进，每阶段保留地图、参数和
rosbag 版本，便于复盘与回退。

验收指标：连续 3 次完成入口—目标点—出口路线；关键点到达误差控制在约 0.3
m 内；识别结果连续 3
帧一致；播报包含目标名称和所在房间；语音或网络异常时仍能通过屏幕、动作或日志完成反馈。
